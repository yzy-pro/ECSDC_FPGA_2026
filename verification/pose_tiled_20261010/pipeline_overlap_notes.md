# 投影与 DDR 加载重叠的备选方案

状态：仅架构分析，尚未实现。当前生产实现仍使用两个完整 tile 槽，在一个生产状态机内依次完成该 tile 的逐像素精确投影和 DDR 源区域加载；它们与另一槽的采样、输出写入并行。当前正在验证 128×64 tile，不应将以下估计当作已通过的性能结果。

可将投影和加载拆为独立状态机。投影完成后，记录该槽的源区域范围、有效性及 `projected` 标记，并尝试占用另一空闲槽继续投影。加载状态机按 tile 顺序读取已投影槽的源区域，全部返回后设置 `ready_tiles`，采样和写入状态机继续保持现有顺序。

最小接口变化：

- 增加加载状态 `ls` 和槽号 `lb`。
- 将源区域的末行、是否有有效像素及投影完成标记保存为每槽元数据。
- DDR 读命令和源 RAM 写端使用 `lb`；坐标写入继续使用投影槽 `pb`。
- 槽的 `occupied` 仍仅在该 tile 最后一个 DDR 输出写入完成后释放，避免复用尚被采样或写出的数据。

坐标 RAM 和源 RAM 已分别具有独立的写入、读取端口，这种分离无需增加 RAM 或投影运算通道。需要重新验证同周期槽状态更新、最后一块、全黑块、反压、错误返回和最终完成时序。

设一个 tile 的投影时间为 A、加载时间为 B、采样及输出提交时间为 C。现有理想稳态周期约为 `max(A+B,C)`。分离状态机但仍只有两个完整槽时，周期下界为 `max(A,B,C,(A+B+C)/2)`，最后一项来自两个槽的驻留时间限制。A 与 C 接近时，最多大约隐藏一半加载时间；不能假定全部 B 都被隐藏。实际收益仍取决于 DDR 竞争及反压。

现有 128×32、自适应 Gamma 版本的综合网表中，源 RAM 使用 64 个 DRM18K，坐标 RAM 使用 11.5 个，输出 RAM 使用 8 个，渲染器合计 83.5 个；整个顶层使用 103 个。128×64 保持源 RAM 容量不变，坐标和输出 RAM 翻倍，估算顶层约为 122.5/134，即 91.4%。此估算需以当前综合结果核实。再增加第三个完整槽会超过现有 RAM 余量。

建议先完成 128×64 的持续帧率和布局布线验证。只有其余量不足时再实施该调度改造，以避免在已满足目标时引入额外的所有权状态。
