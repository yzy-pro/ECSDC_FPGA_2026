## 当前实现

`hdmi_ddr3_top` 默认 `POSE_CORRECTION_ENABLE=1`，实际进入 `fram_buf_pose`，
旧八分区和 `imu_affine_q14` 仅保留为参数选择的历史路径。
这是完整帧级大角度功能实现；HDMI 扫描保持 1920×1080@60 Hz，但渲染器尚不满足 30/60 个新矫正帧每秒。

- 忽略 roll，绝对 yaw/pitch；yaw 绕向上轴右手为正，pitch 低头为正。
- 每轴饱和到 ±1251 Q2048 弧度，约 ±35°。没有源像素偏移限幅。
- 在源帧 SOF 锁定姿态；源帧完成且全部 DDR 写提交后，渲染器取得源帧及其姿态。
- 模型为逆相机旋转/透视投影，再应用真实镜头标定；校准值来自 `calibration/camera_20260930.json`。
  标定为 MATLAB 的 1 起始像素坐标；映射输入加 1、输出减 1 后访问 0 起始 DDR 图像。
- 后方射线、超出标定多项式保护半径、图像边界或缺少双线性四邻点输出黑色。
- 默认最近邻，`INTERPOLATION_MODE=0` 双线性，后者采用 Q5 小数权重。

## 存储与所有权

```text
采集 RGB888 → adaptive_preprocess_stream → RGB565 → 异步 FIFO → 16 beat 突发写
                                                                        ↓
                                                           DDR 源 slot 0
                                                                        ↓
源帧姿态 → 流水投影 → 每组 16 个坐标 → 256 字源缓存/随机读取 → 插值/打包
                                                                        ↓
                                                           DDR 结果 slot 1/2
                                                                        ↓
                              VS 请求/排空/确认 → 16 beat 线性读 → 异步 FIFO → HDMI
```

DDR 地址单位为 32 bit；一个 256 bit beat 占 8 个地址单位。
slot 起点为 `bank << 22`，因此槽间距是 **16 MiB**，不是 4 MiB。
1920×1080 RGB565 每帧 4,147,200 B，实际采用源 slot 0 与结果 slot 1/2。
渲染时源 slot 不写入；结果 slot 不能是正在显示或等待发布的槽。
当前控制器串行完成一次采集、渲染、发布后再请求下一源帧；未被请求的输入帧跳过。

捕获端先收齐最多 16 个 256 bit 字，再向 arbiter 原子提交整组地址/数据/长度。
没有 WVALID 的厂商写接口因而始终有完整数据可取；显示读命令发出前预留整组 FIFO 容量。
读写通道分别最多一个事务在途，采集写和显示读优先，渲染读写使用单拍命令。
只有真实尾拍完成后才通知上层，错误 LAST/ID 会锁住对应通道，避免发布不完整结果。

显示 VS 发出请求后，像素端排空旧 FIFO；DDR 端等待旧读结束且 FIFO 空，再切换槽并确认。
像素端收到确认、结束清空，再通知 DDR 可以读新帧。该握手避免延迟返回和连续 VS 导致旧帧混入。
显示欠载后本帧余下部分置黑并排空，下一 VS 恢复，不将晚到像素移到错误列。
输入短帧/FIFO 溢出会标记无效、排空已排队写入，然后重试，禁止送入渲染器。

片上主要缓存为两个 512×256 bit 异步 FIFO、一个 256×256 bit 渲染源字缓存，以及突发/坐标寄存器。
不再使用静态畸变带状缓存，因此大角度读取不依赖旧缓存窗口。

## 预处理与配置边界

`adaptive_preprocess_stream` 位于输入 RGB888 到 RGB565 之前，默认关闭且零延迟旁路。
mode 0 旁路，mode 1 固定增益/偏置，mode 2 外部可编程 LUT；帧统计在帧边界锁存。
已修正 mode 0 与高增益有符号位宽问题。顶层 LUT 写口当前固定关闭；
自动曝光、Gamma 自适应、直方图算法和帧原子 LUT 提交尚未实现，不能把此接口视为进阶预处理算法完成。

参数适用范围：H 为 16 的整数倍、H/V 在 11 bit 坐标范围内、地址宽度至少 24、
FIFO_BITS 建议不低于 5。生产参数固定为 H=1920、V=1080、ADDR_WIDTH=28、FIFO_BITS=9。

### 帧率瓶颈定位

本次整帧共 2,073,600 像素、129,600 个 16 像素批次，用时 17,806,679 个 100 MHz DDR 时钟：
平均 **137.55 时钟/批次、8.59 时钟/输出像素**，折合约 **11.65 Mpixel/s、5.62 fps**。
1080p60 要求 124.416 Mpixel/s，即 100 MHz 下每拍至少 1.244 个输出像素；当前整帧吞吐约为目标的 9.4%。
1080p30 也需 0.622 pixel/clock，当前吞吐约为其 18.7%。

主因在 `pose_renderer_dma` 的批处理调度，不是 HDMI 扫描频率：

1. **投影器批次屏障反复支付流水延迟。** 投影器能每拍接收一个坐标，但 renderer 只发完 16 个坐标后等待本批 16 个结果全部返回，再开始采样；采样和写回期间投影器闲置。投影器含 42 级逐位除法流水线及前后定点处理级，因而每批都要经历填充/排空，固定开销不会因黑边减少。
2. **采样路径每次只处理一个像素。** 状态机对每个有效像素依次执行地址查找、cache tag 判断、取像素/等待 DDR、打包；同一时刻至多有一个 renderer 读事务在途。16 个结果没有形成可并行消费的采样队列。
3. **读缺失延迟没有隐藏。** 全帧只有 125,509 次源 word read，平均每输出像素 0.0605 次、每批 0.969 次；但每次 miss 都经过单拍命令握手和返回等待，之后才继续下一个样本。测试模型还加入命令背压及 3～8 周期读返回延迟。这些是验证模型延迟，板上实际分布需要测量。
4. **写回也形成批次串行屏障。** 每批 16 像素都要提交一次 256-bit 写并等待 `wr_done`，全帧固定 129,600 次；当前批写完成后才启动下一批投影。测试模型再加入写命令等待和 4～10 周期完成延迟。
5. **黑边只省源读，不省输出工作。** 本次 1,046,752 个像素为黑色，因此没有源 DDR 读取，但仍然逐像素投影、查有效标记、写入黑色结果；结果帧写回仍是整帧固定工作量。

上述结构共同导致 137.55 周期/批次。已有仿真只统计总周期和 DDR 事务数，没有分别累计投影等待、cache hit/miss、命令背压、读返回和写完成等待，因此不能从当前日志可靠声称各因素分别占用多少周期。可以确定的是批次投影屏障、逐像素串行采样、单 outstanding 读和逐批同步写回；测试模型的确定性停顿会放大总耗时，但不是架构瓶颈的来源。

优化应先让投影坐标进入独立 FIFO，使下一批投影与当前批采样/写回重叠；再给 renderer 读加入多个 outstanding 请求及返回队列，并按连续源 word 合并/预取；写回侧用 FIFO 隔离 `wr_done`。之后再评估双像素/拍投影及并行采样。若使用双线性插值，四个邻点也应按 word 复用，否则串行 tap 查询会进一步增加周期。单纯提高 HDMI 时钟或放宽角度不能解决上述吞吐限制。

100 MHz 单像素/拍的理想计算上限仅 48.23 fps，尚未计入 DDR，无法到 60 fps；双像素/拍理论上限 96.45 fps，才可能给访存与控制留下余量，但这不是端到端帧率保证。当前 HDMI 仍按 60 Hz 扫描并重复显示最近一张完整矫正帧。

### 缓存扩容实验

已将 renderer 的源字缓存改为可配置，并把默认容量从 256 行（8 KiB 数据）扩为 1024 行（32 KiB 数据）：
`CACHE_INDEX_BITS=10`。该参数已贯通 `pose_renderer_dma`、`fram_buf_pose` 和顶层
`POSE_CACHE_INDEX_BITS`，测试平台可用 `--cache-index-bits` 扫描。
同一 1920×1080、yaw=+30°、pitch=-20°、最近邻模型的结果如下：

| 缓存行数 | 源 DDR 读 | 总周期 | 模型帧率 |
|---:|---:|---:|---:|
| 256（8 KiB） | 125,509 | 17,806,679 | 5.62 fps |
| 512（16 KiB） | 92,965 | 17,543,164 | 5.70 fps |
| 1024（32 KiB） | 75,834 | 17,403,899 | 5.75 fps |

1024 行缓存使源读减少约 39.6%，但总周期只减少约 2.3%，因此扩容缓存是有效的带宽优化，
不是当前帧率的主要解法。它仍然属于直接映射源字缓存，不是完整的输出 tile 预取器；要继续减少
DDR 事务，应按 64×64 输出 tile 计算包含四邻点的源包围盒，使用双缓冲源 tile、连续突发预取和
坐标 FIFO，并让下一 tile 的投影/预取与当前 tile 的采样/写回重叠。64×64 方案的片上容量预算见
`20261009_pose_1080p60.md`，128×128 按当前三阶段缓存组织会超过全芯片 DRM 容量。

### 查表加速的边界

当前投影器已对 sin/cos 使用一度表加线性插值；其余主要开销是 ray-z 除法、畸变乘法和焦距乘法。
当前已增加可选 `pose_reciprocal_lut.v`：对正 Q18 ray-z 做指数归一化，使用 256 项 Q16
倒数 ROM 和线性插值，再以乘法得到 x/z、y/z。`RECIPROCAL_LUT_ENABLE` 贯通投影器、DMA、
帧缓存和顶层，默认值为 0，保持现有精确恢复除法器；设为 1 可在 ModelSim 中比较吞吐和资源。
随机 20,000 个有效射线测试的最大商误差为 22 个 Q18 LSB（约 0.000084，远小于一个像素），
但仍需重新综合、布线和板测确认 ROM 推断及乘法路径时序。ROM 必须按 Q18 输入范围覆盖 `z>0`
及边界保护，并与当前逐位除法器做逐样本误差对比；
不能把完整 yaw/pitch/像素坐标映射预存为 Flash 表，因为表规模随分辨率和姿态组合快速膨胀。
外部 Flash 也不适合作为每像素随机查表存储，建议综合为配置初始化的片上 ROM/DRM。
在 reciprocal LUT 的误差、资源和时序验证完成前，默认仍使用现有除法器；缓存扩容不会改变几何结果。

## 分块预取试实现（2026-10-10）

为验证“连续源字一次突发读取”的收益，`pose_renderer_dma` 新增可选参数
`CACHE_LINE_WORDS` 和 `rd_cmd_len`，缓存 miss 可以按 1、2、4 或 8 个相邻
256-bit 源字发起一次读取；`pose_ddr_arbiter` 同时增加 renderer 读突发长度，
仍然校验每个返回 beat 的 `RLAST`，并把每个 beat 写入独立 cache tag。`fram_buf_pose`
和顶层通过 `CACHE_LINE_WORDS`/`POSE_CACHE_LINE_WORDS` 贯通，回归平台可用
`tests/run_pose_renderer.py --cache-line-words N` 选择配置。

该路径已经通过随机 DDR 停顿、RVALID 间隙、帧尾短突发、错误 LAST、nearest/bilinear
和完整帧缓存集成测试。1080p、100 MHz 行为模型的对照结果为：

| 配置 | 源读命令 | 单帧周期 |
|---|---:|---:|
| 单字（N=1） | 75,834 | 17,403,899 |
| 四字预取（N=4） | 75,318 | 17,669,164 |

当前 renderer 每次只消费一个输出采样，且 DDR 仲裁器一次只允许一个读事务；连续 line
预取因此带来的命中增加很小，反而增加了无效过取和返回等待。基于实测，顶层默认仍为
`POSE_CACHE_LINE_WORDS=1`，四字模式保留为可选实验接口；要真正提高帧率，应继续实现
输出 tile 的包围盒预取、双缓冲源 SRAM、坐标 FIFO，并将下一 tile 的 DDR 填充与当前
tile 的采样/写回重叠，而不是只扩大单采样 cache miss 的突发长度。

投影器采用归一化、yaw/pitch 旋转、除法、畸变多项式、焦距乘法、边界判断流水线；
`pose_load` 后必须等到 `pose_ready` 才能送首像素，渲染器已处理该等待。
半径平方采用 20 bit 乘法，因为所有可发布像素均满足 `0 <= r2 <= 600000 < 2^20`，
完整 r2 仍传播至越界判断；缩小该乘法不改变有效像素或黑边结果，也不改变流水延迟。
归一化坐标的平方/交叉乘积采用有符号 20 bit 操作数：候选射线的坐标比值严格位于 ±2 内，
Q18 商可以精确存入有符号 20 bit；非候选射线的除法分子为零，并最终输出黑色。
FIFO 同步器包含 PDS 原生 `PAP_ASYNC_REG=1` 标记，保护同步寄存器并引导相邻放置。
四组 Gray 指针总线另有 6.734 ns 的 `set_max_skew` 约束，原有异步时钟组保持原样；
`audit_pose_fifo_cdc.py` 独立检查快/慢两个工作角、四组共 40 位指针的报告覆盖和裕量。
PDS 普通文本汇总可能在 skew 失败时仍显示通过，构建脚本因此强制检查 XML skew 报告。
上述专属约束/审计针对默认位姿路径，改用历史路径时需要相应调整。

此前 `pose_tile_interfaces`、八分区和小偏移候选位流不包含本路径。
仿真不代替实际 IMU 安装方向、旋转组合顺序、图像质量和板上吞吐测试。
