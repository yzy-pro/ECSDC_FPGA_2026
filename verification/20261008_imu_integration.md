# IMU 动态仿射接入记录（有界集成版本）

此文档记录 2026-10-08 历史版本。2026-10-09 用户确认忽略 roll、yaw 向上轴为正、
pitch 低头为正并使用绝对角度，当前源码与测试见 [Yaw/Pitch 接入记录](20261009_yaw_pitch.md)。
下方 roll 算式和位流不对应新源码。

## 功能与范围

参考 `reference/imu_cboard` 的协议，将姿态接入现有 1920×1080 HDMI/DDR 链路。
镜头标定参数不随姿态变化；当前是在静态去畸变采样坐标之后追加有界仿射变换。
此版本验证通信、跨时钟域、逐帧更新和动态缓存访问，尚不满足“任意角度”的完整高阶任务。

接口：50 MHz 系统时钟，UART 921600 baud、8-N-1，帧格式如下。

```text
55 AA yaw_lo yaw_hi pitch_lo pitch_hi roll_lo roll_hi checksum 0D
checksum = 六个姿态字节相加的低八位
angles = 有符号 int16，小端，Q2048 rad
```

IMU/STM32 的 3.3 V TTL TX 接 FPGA `AB4`（参考扩展接口 35 脚），双方共地。
不要将 RS-232 电平接入该引脚。默认启用 `ATTITUDE_WARP_ENABLE=1`。
设为 0 时角度置零，仍经过相同 23 拍视频流水链。

`imu_protocol_50m` 发布一组完整姿态并翻转 toggle；`attitude_cdc` 将快照送入
pixel_clk 域。协议帧相隔至少约 108.5 us，数据保持时间远长于同步延迟。
`undistort_rd_buf` 暂存最新快照，在输出 VS 上升沿锁存，同一帧使用相同姿态。
顶层添加 sys_clk 域复位释放同步器和 sys_clk/pixel_clk 异步约束。

`imu_affine_q14` 使用三拍流水计算：

```text
tx = clamp(yaw * 128, -32768, 32768)       [Q14 pixel]
ty = clamp(pitch * 128, -32768, 32768)     [Q14 pixel]
a  = clamp(roll, -2, 2) / 2048
u  = x + tx - a*(y-cy)
v  = y + ty + a*(x-cx)
```

乘积按算术右移向负无穷取整。yaw/pitch 增益为 16 像素/rad，最多各平移 2 像素；
roll 上限约 0.056°，不是任意角度旋转。该增益用于受限范围的工程集成，并非实测
相机运动模型。真正姿态补偿还需要明确 IMU 与相机坐标轴、外参、参考姿态和补偿方向，
将旋转/投影与镜头模型正确组合。

## 缓存

旧静态预取表不能支持上一版 ±32 像素偏移。现生成器覆盖源坐标 x/y 各 ±4 像素，
包括跨 240 像素分区边界、双线性邻点、提前两行预取和上一行流水线残留。
分区源行容量为 `58,56,26,18,18,28,68,58`。
每奇偶 RAM 2475 字，字宽 272 位，包含 16 像素及右邻点，颜色格式保持 RGB565。
物理存储拆成 2048+427 字，避免 PDS 将整块向上取整为 4096 深度。
访问延迟不变，仿真与综合使用同一拆分实现。

- 仿射 21,609 组有符号算术、正负旋转、平移、饱和及 ±4 像素包络。
- 输入配对、RGB 扩展、23/2 拍 DE、DDR 尾拍、缓存 halo、帧重启和真实读适配器。
- 旧缓存别名、早结束、切向流水错位的故障注入均被检测到。
- 最近邻、双线性各连续 3 帧动态测试，各 6,220,800 像素及四邻点检查通过。
- 连续帧切换 bank，帧中发送正负极值姿态，验证下一 VS 生效和帧内锁存。
- 独立静态坐标映射回归和不匹配标定的 elaboration 拒绝检查。

## 后续大角度工作

不能通过扩大 `clamp` 直接实现。大角度旋转的源行跨幅会超过现有 band cache，
需要按 tile/块组织 DDR 读请求及重采样，再加入 sin/cos 或完整姿态投影计算、
参考姿态归零和相机/IMU 坐标轴标定。应针对完整角度范围证明带宽、缓存与时序，
然后进行真实相机联动的板测与图像质量评估。

已完成平面内大角度的逐像素分块设计评估，见
[大角度旋转缓存评估](20261008_rotation_tiles.md)。评估脚本及数据可复现，
它们尚未接入 RTL，也不是大角度功能或真实帧率的验证结果。
