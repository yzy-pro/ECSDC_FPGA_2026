# 基于紫光同创 FPGA 的任意角度畸变矫正系统设计报告

## 摘要

本项目基于紫光同创 PGL50H-FBG484-6 FPGA 和 Pango Design Suite，设计了一套面向 1920×1080 视频流的相机畸变与姿态矫正系统。系统接收 HDMI 视频，在输入侧完成帧自适应 Gamma 预处理和 RGB 格式转换，使用 DDR3 保存源帧；矫正器依据相机标定参数和每帧锁存的 IMU yaw、pitch，对输出像素进行逐像素逆投影，并通过分块缓存和 DDR 突发访问生成矫正帧，最终按 60 Hz HDMI 时序显示。

2026-10-22 的当前默认实现采用 128×32 分块、最近邻采样，并支持 CP2102 控制三个独立开关；yaw/pitch 工作范围约为 ±15°，roll 暂不参与变换。当前版本完整链路并发 RTL 仿真达到 30.000030 个新矫正帧/秒，最终 PDS 快/慢角时序、FIFO Gray 偏斜及位流身份审计通过。第 6 节保留的四组压力测试和历史资源数据来自 2026-10-10 的 128×64 基准版本，当前版本的独立验证见第 7.6 节。位流尚未烧录开发板，实际帧率、端到端延迟和图像质量仍待测量。

**关键词：** 紫光同创 FPGA；镜头畸变矫正；逆投影；IMU；DDR3；分块流水线；自适应 Gamma

## 1. 题目要求与设计目标

题目要求实现视频采集、缓存和显示链路，在 FPGA 中完成基于相机标定参数的畸变坐标映射及图像重采样；高阶目标包括随相机姿态变化的动态矫正、实时流水线处理和自适应图像增强。测评还关注矫正精度、实时帧率、资源占用、时序约束和工程文档。

本设计将这些目标具体化为：

- 处理分辨率为 1920×1080，输入与 HDMI 显示扫描为 60 Hz。
- 以真实相机标定数据为几何矫正参数；输出保持完整 1920×1080 视场，不裁切、不调整输出焦距。
- 每帧在源帧起始时锁存 IMU 绝对 yaw/pitch，在约 ±15°范围内进行姿态补偿；当前忽略 roll。
- 默认分块矫正路径在 DDR 负载、总线竞争和刷新停顿模型下达到至少 30 个不同源帧/秒。
- 以 RTL 回归、完整链路仿真、PDS 综合与布局布线报告作为当前工程验证证据；板级测量单独列为后续工作。

## 2. 系统总体结构

系统由 HDMI 视频接口、预处理与格式转换、帧缓存、姿态/坐标计算、分块渲染、DDR3 仲裁、显示扫描和 IMU 接收等部分组成。主工程为根目录的 `EmbFPGA.pds`，应用 RTL 位于 `src/`，厂商 PLL、RAM 和 DDR3 IP 位于 `ipcore/`。

```text
HDMI 输入 RGB888
      │
      ├─ 输入寄存器 → 帧自适应 Gamma → RGB565
      │                                │
      └─────────────────────────────── DDR3 源帧槽 (0/3)
                                         │
IMU UART → 姿态解析 → SOF 锁存 yaw/pitch
                                         │
                         逐像素逆投影 + 128×32 分块调度
                                         │
                       源矩形突发读取 → 双源 SRAM 槽
                                         │
                            最近邻采样 → 块缓存
                                         │
                     DDR3 结果帧槽 (1/2) → VS 时交接
                                                    │
                                             HDMI 60 Hz 输出
```

采集、渲染和显示并行工作。DDR3 帧槽划分为源槽 0/3 和结果槽 1/2；结果只有在写回完成并到达显示帧边界后才发布。异步 FIFO 用于跨越像素时钟域与 DDR/渲染时钟域。帧级姿态锁存和结果帧交接避免单帧中途改变变换参数或显示未完成的帧。

## 3. 相机模型与姿态矫正

### 3.1 标定数据

系统采用用户确认的 MATLAB `cameraParams` 标定结果，记录于 `calibration/camera_20260930.json`。图像大小为 1920×1080，内参矩阵按 MATLAB 存储约定为：

\[
K = \begin{bmatrix}
748.4469 & 0 & 0 \\
0 & 748.0773 & 0 \\
944.9033 & 522.3963 & 1
\end{bmatrix}
\]

径向畸变系数为 \(k_1=0.0099\)、\(k_2=-0.0434\)，切向系数 \(p_1=p_2=0\)。该参数文件注明像素坐标原点为 1；RTL 中涉及坐标转换时需遵守对应的像素中心/坐标约定。输出采用与输入相同的内参，不进行裁切或额外焦距调整。

### 3.2 逆映射及重采样

矫正采用逆映射：对每一个输出像素坐标，根据输出内参建立归一化视线，结合该帧的姿态变换和镜头畸变模型，计算其在输入图像中的采样位置。这样由输出端逐点发起采样，避免正向映射时多个输入像素争写同一输出位置以及输出空洞难以补齐的问题。

坐标计算使用定点流水线。默认分块渲染器对块中每一个输出像素计算准确的逆投影坐标，再统计有效采样坐标的包围矩形；渲染器按行从 DDR 读取源区域至片内 SRAM，完成采样后将输出块突发写回结果帧。块内使用精确逐像素坐标，不以块平移或稀疏网格近似取代投影。

当前默认重采样方式为最近邻。若逆映射位置在有效输入范围之外，则该输出像素按视野外策略输出黑色；因此系统没有额外填充或拉伸视野外图像内容。题目提及的双线性插值在历史串行路径中保留，但当前达到 30 fps 仿真结果的分块默认路径不使用双线性。黑边/空洞是否达到视觉验收标准仍须用实际测试图卡和开发板输出进行确认。

### 3.3 任意角度动态矫正

IMU 数据经 UART 接收和协议解析后，通过 CDC 同步进入矫正控制域。系统在每个源帧起始处锁存绝对 yaw/pitch，使整帧使用同一姿态快照。默认 yaw/pitch 量化范围为 ±536 Q2048，约 ±15°；roll 当前忽略。角度变化通过后续帧更新，因而属于逐帧动态姿态补偿，不是帧内运动补偿。IMU 安装方向和实际角度精度需要在板级调试时标定确认。

## 4. 图像增强与视频时序

输入侧默认启用帧自适应 Gamma。控制逻辑根据输入帧亮度统计和暗部/高光比例，从七档曲线中选择增强曲线；场景分类连续稳定后才更新目标，并限制每帧最多变化一档。Gamma 在 RGB565 转换前执行，输入寄存器、Gamma 和格式转换构成固定四拍流水线，视频控制信号随数据同步延迟。自动模式下关闭输出端固定 Gamma，避免重复校正。

HDMI 输入和输出时序为 1920×1080、60 Hz；DDR/渲染时钟为 100 MHz。显示端按帧边界接收已经完成写回的矫正帧。输入、输出视频扫描可以继续运行并重复显示旧帧，但重复帧不计入新矫正帧率。

## 5. 分块架构与存储管理

当前默认输出块尺寸为 128×32，共 15 列、34 行，最后一排为 24 行，总计 510 块。两个源 SRAM 槽交替工作，使下一块投影/源区域读取可与当前块采样/结果写回重叠。两个槽合计坐标 RAM 为 8192×23 bit，输出块 RAM 为 512×256 bit；每个源缓存槽仍为 2048×256 bit，即 64 KiB。采集和显示异步 FIFO 各为 512×256 bit。写回使用客户端持有的分布式 RAM 突发缓冲，直到最后一个 WREADY/WLAST 传输才释放，避免在仲裁器中复制 4096 bit 突发数据。

源区域容量检查在发出 DDR 读请求前完成；超出缓存容量时拒绝该块读取，避免覆盖片内缓存。针对当前相机标定和 yaw/pitch 限值的保守区间分析给出 128×64 块源数据上界 1529 beats，小于单槽 2048 beats。该分析由软件算术区间模型提供，不是 HDL 形式证明。帧槽所有权与最后一次 DDR 写完成状态共同约束结果帧发布，避免仍在写入的帧被显示或被下一次渲染覆盖。

## 6. 验证方法与结果

### 6.1 RTL 与完整链路仿真

完整链路测试实例化实际帧缓存 wrapper、异步 FIFO、分块渲染器和 DDR 仲裁器，使用 1920×1080、148.5 MHz 像素时序。最终压力测试使用 32 拍 DDR 命令基础延迟、25% 随机数据停顿、读写共享每时钟一个 256 bit 数据 beat，并分别施加两种刷新停顿：每 780 拍暂停 35 拍，以及每 6120 拍暂停 250 拍。Gamma 开启的测试还检查输入寄存器、Gamma 和 RGB565 转换数据。

| Gamma | 刷新压力 | 最慢渲染时间 | 最大新帧发布间隔 | 新矫正帧率 | 结果 |
|---|---:|---:|---:|---:|---|
| 关闭 | 35 / 780 拍 | 32.39052 ms | 3,333,330 拍 | 30.000030 fps | 通过 |
| 关闭 | 250 / 6120 拍 | 32.25987 ms | 3,333,330 拍 | 30.000030 fps | 通过 |
| 开启 | 35 / 780 拍 | 32.40717 ms | 3,333,330 拍 | 30.000030 fps | 通过 |
| 开启 | 250 / 6120 拍 | 32.25533 ms | 3,333,330 拍 | 30.000030 fps | 通过 |

每组测试覆盖 11 组姿态、28 个输入帧并发布 13 个不同源帧的矫正结果；每组检查 51,840,000 个显示像素，四组累计检查 207,360,000 个显示像素，未发现测试定义范围内的采集、Gamma、像素、帧身份、DDR 协议或帧槽所有权错误。yaw=-144、pitch=0 的附加定向压力测试最慢渲染时间为 32.45705 ms，仍通过 30 fps 帧发布约束。仿真使用的 DDR 停顿是可重复的压力模型，不代表所有真实 DDR 调度和板级系统负载。

### 6.2 PDS 实现与时序检查

2026-10-10 归档候选的最终 PDS 构建针对快、慢两个工作角完成综合、布局布线和时序审查。最终报告为 **All Constraints Met**。慢角 100 MHz DDR/渲染域 setup 最小余量为 +0.462 ns；148.5 MHz 输出像素域为 +0.853 ns。输入像素域慢/快角 setup 余量分别为 +0.927 ns 和 +0.121 ns。所有时钟域最小 hold 余量均为正值，慢角最小 +0.114 ns，快角最小 +0.054 ns。

四组异步 FIFO Gray 指针总线的双角偏斜约束均满足，最坏 skew 为 1.687 ns，小于 6.734 ns 限值。布局布线占用 122/134 个 DRM 位置（约 91.04%；工具显示 92%），LUT 为 19,352/42,800，寄存器为 25,756/64,200，APM 为 45/84。以上资源数为最终实现报告记录，具体占用会随工具版本或构建配置变化。

### 6.4 帧率与处理周期预算

一帧有效图像包含：

\[
N=1920\times1080=2,073,600\ \text{pixels}
\]

1080p60 的扫描总时序为 2200×1125，在 148.5 MHz 像素时钟下，扫描周期为 16.667 ms，有效像素速率为 124.416 Mpixel/s。矫正器目标为每秒完成 30 个不同源帧，因此平均有效处理需求为 62.208 Mpixel/s。在 100 MHz 渲染时钟下，每帧周期预算为：

\[
C_{30}=\frac{100\times10^6}{30}=3,333,333.33\ \text{cycles}
\]

现有最终源码定向压力测试的最慢观测值为 3,245,705 拍，即 32.45705 ms，距预算约有 87,628 拍、0.87628 ms，时间余量约为 2.63%。该帧平均消耗约 1.565 个渲染时钟/输出像素，包含投影、读取、采样、写回和竞争等待。投影流水线及块内采样流水线各自可以每拍启动一个像素，但整帧吞吐还受 DDR 命令、块切换和总线竞争影响。

HDMI 保持 60 Hz 扫描，只说明显示接口持续输出。性能统计以发布的不同源帧为准：在测试稳态下约每两个扫描帧更新一次矫正结果。当前数据支持 1080p30 新帧处理目标，不能据此宣称 1080p60 矫正吞吐，也未证明全部姿态及所有 DDR 调度下的最坏执行时间。

### 6.5 延迟构成与测量口径

输入四拍预处理流水线在 148.5 MHz 下约为 26.94 ns；一次完整渲染的观测耗时约为数十毫秒。这两者对应不同阶段。系统还需要等待源帧采集完成、调度渲染、等待结果写回确认，以及等待输出 VS 发布，因此不能把 32.45705 ms 当作端到端延迟。

以源帧输入 SOF 到对应结果帧输出 SOF 为帧延迟口径，可按下式分解：

\[
T_{\mathrm{SOF\to SOF}}=T_{\mathrm{capture}}+T_{\mathrm{queue}}
+T_{\mathrm{render}}+T_{\mathrm{publish}}
\]

其中，采集阶段包含从输入 SOF 到源帧提交的时间，排队时间取决于渲染器和帧槽状态；渲染时间以调度开始至最终写回确认为准；发布等待由显示时序和交接条件决定。若测量输入某个像素至输出对应像素，还需考虑两端扫描位置。现有归档未给出上述口径的完整延迟实测，报告暂不填入估算总值。板测时应通过源帧编号或同步标记关联输入/输出，记录最小、平均、最大延迟，并单独说明相机曝光、HDMI 桥和显示器是否计入。

### 6.6 DDR 有效数据带宽分析

RGB565 每像素占 2 字节，一帧有效图像数据为 4,147,200 字节，约 3.955 MiB；相较 RGB888 减少三分之一的有效像素存储量。256 bit 用户接口的每个 beat 可承载 16 个 RGB565 像素，完整帧对应 129,600 beats。以下按十进制 MB/s 计算，不包含 DDR 命令和等待开销。

| 数据流 | 分析条件 | 有效数据带宽 |
|---|---|---:|
| 输入采集写入 | 按全部 60 fps 均写入计算的预算值 | 248.832 MB/s |
| 显示读取 | 60 Hz 每次扫描读取完整结果帧 | 248.832 MB/s |
| 矫正结果写回 | 每秒写回 30 个完整结果帧 | 124.416 MB/s |
| 渲染源区域读取 | 128×64 零姿态独立测试为 129,636 beats/帧，按 30 fps 折算 | 124.451 MB/s |
| 上述合计 | 采集按 60 fps 预算，源区域读取采用该零姿态样本 | 约 746.531 MB/s |

该表是带宽预算示例。完整链路可能跳过部分输入帧，实际采集写入量依帧槽调度而定；姿态变化会改变源矩形大小及相邻块重复读取，零姿态读取量不是全角度上界。例如软件姿态扫描在 yaw=-144、pitch=0 处记录到 134,225 个源读取 beats/帧。因而，平均有效字节量充足并不能单独证明实时性，还必须检查突发长度、读写切换、刷新、命令延迟和 FIFO 峰值。

压力模型中共享数据通道的理论上限为 32 字节×100 MHz=3.2 GB/s；这只是模型用户数据接口峰值，不能作为开发板 DDR3 的实测持续带宽。四组最终压力测试中采集 FIFO 峰值分别为 8、28、8、28 个条目，均低于 512 条目容量，为已覆盖场景的缓冲余量提供了证据。该指标来自仿真，不是实际板卡监测值。

### 6.7 资源效率与架构取舍

| 资源 | 最终布局布线使用量 | 器件可用量 | 占用率 | 剩余量 |
|---|---:|---:|---:|---:|
| LUT（含常量及旁路） | 19,352 | 42,800 | 45.21% | 23,448 |
| 寄存器 | 25,756 | 64,200 | 40.12% | 38,444 |
| APM 运算资源 | 45 | 84 | 53.57% | 39 |
| DRM 物理位置 | 122 | 134 | 91.04% | 12 |

当前资源瓶颈是片内存储。两个 64 KiB 源缓存槽、双块坐标缓存、输出块缓存和异步 FIFO 以增加片内存储占用换取 DDR 突发效率和并行处理能力。综合报告采用 DRM18K 等效容量口径，为 121/134；最终物理位置口径为 122/134，包含 120 个 DRM18K 和 2 个 DRM9K，两种数值应分别引用。

源缓存容量分析上界为每槽 1529/2048 beats，剩余 519 beats，即约 25.34% 的槽内容量。该容量余量用于说明当前标定及限定角度下的单块容纳能力，与器件剩余 DRM 数量、帧率余量是不同指标。

2026-10-10 的早期 128×32 块在一次共享总线、刷新及随机停顿组合测试中曾耗时 3,349,830 拍，超过 30 fps 预算，因此当时扩大为 128×64。2026-10-22 版本重新采用 128×32，配合连续同步 RAM 行装载与共享写数据通路，当前含全部八种开关组合的完整并发测试最慢渲染 3,314,614 拍，通过 30 fps 帧发布约束，同时减少片上存储和宽寄存器需求。两次结果对应不同 RTL 与测试配置，不能仅凭块尺寸比较性能；进一步调整参数或接入双线性采样仍需重做容量、资源和时序分析。

### 6.8 时序优化对性能的影响

首轮 128×64 实现的慢角 setup WNS 为 −0.791 ns，关键路径串联了包围矩形宽高计算、面积乘法和容量比较。当前 RTL 将其划分为 `P_BOUNDS`、`P_AREA`、`P_CAPACITY` 三个阶段，通过寄存器隔开组合逻辑，最终 DDR/渲染域慢角 setup 余量达到 +0.462 ns。

该修改每个有效块增加两拍，255 个块最多增加 510 拍，即 5.10 µs，约占 30 fps 帧预算的 0.0153%。它以很小的调度开销换取时序收敛，不改变像素投影公式和源缓存容量。相关容量边界回归覆盖“面积等于容量”“面积超限且不发 DDR 请求”和“全黑块不误用陈旧面积”等情况，最终完整链路压力测试也已重新执行。两轮构建约束和其他路径可能影响各自 WNS，不能把两个余量的差值直接当作统一路径的性能增益。

### 6.9 精度、图像质量与证据适用范围

分块渲染测试检查输出坐标覆盖、每个输出像素、源帧身份和写回完成，其中坐标参考来自另一个投影器实例。因此其主要证明调度、缓存和采样实现符合参考投影器，不能单独证明真实光学模型误差或独立浮点几何精度。软件网格近似研究尚未接入默认 RTL，其误差数据也不能写作当前系统测得的图像误差。

当前仍缺少统一口径的定点坐标相对独立浮点模型的最大/RMS 误差，以及板上 MTF50/SFR、直线度和视野外黑色区域比例。提交最终报告前，应补充测试图卡、输入姿态、标定文件版本、采样方式、原始/矫正图像及测量方法，并分别列出坐标量化、最近邻重采样和 RGB565 量化的影响。

## 7. 工程规范与文档

### 7.1 模块化组织与接口边界

工程按顶层集成、板级接口、IMU、时序、预处理、格式转换、帧缓存、姿态矫正和厂商 IP 分层。顶层负责连接和配置；投影器负责几何计算；分块渲染器负责块内数据组织；仲裁器负责 DDR 事务；FIFO 负责跨时钟域缓冲。这些边界支持分别测试坐标算法、总线协议和跨域行为，减少算法变化对板级接口的影响。

模块接口通过 `valid/ready`、`start/busy/done/error` 和帧/块所有权表达数据有效性与事务状态。DDR 地址以 32 bit word 为单位，载荷以 256 bit beat 为单位；渲染器的 `wr_done` 表示实际写事务完成，不能用写命令被接受代替。`pose_load/pose_ready` 区分姿态装载与像素投影启动，输出 `map_valid` 区分几何无效坐标与正常输出流水线有效信号。

分辨率、块大小、缓存位宽和功能开关由参数配置，但参数可修改不等于全部组合已经验证。当前报告的性能数据仅适用于归档候选配置。厂商 IP 通过 `.idf` 登记到 PDS 的 IP 列表；应用 RTL、约束和 IP 文件分目录管理，主工程清单与构建/测试脚本共同维护路径。

### 7.2 时序约束的依据与覆盖

约束文件为 `src/constraints/hdmi_ddr3_top.fdc`，除引脚和电气属性外，还覆盖主时钟、派生时钟、I/O 时序预算、异步时钟关系和 FIFO 总线偏斜。

| 约束对象 | 当前约束与设计依据 | 审查重点 |
|---|---|---|
| 基础时钟 | `sys_clk` 20 ns、`video_ref_clk` 37.037037 ns、`pixclk_in` 6.734 ns | 与 50 MHz 系统参考、27 MHz 视频参考及 148.5 MHz 输入相对应 |
| 派生时钟 | 在 PLL/分频器输出引脚建立 DDR 核心、PHY、视频及配置时钟 | 保留时钟来源和倍分频关系；正常同步数据路径保持时序分析 |
| HDMI 输入 | 输入延迟最大 +2.000 ns、最小 −0.500 ns | 当前为板级接口预算，仍须与桥芯片参数、板级走线及实际采样关系核对 |
| 输入首级采样 | 对 RGB、DE、VS 到首级输入域寄存器设置零周期 setup 关系 | FDC 注释说明同一发送边沿捕获意图，属于收紧建立时间检查；需同时检查 hold |
| HDMI 输出 | 输出延迟最大 +1.500 ns、最小 −0.500 ns；以反相生成时钟描述 MS7210 下降沿采样 | FPGA 物理输出时钟保持原极性；反相约束表达采样边沿 |
| 时钟不确定度 | 对文件列出的生成时钟及视频参考时钟设置 0.200 ns setup/hold 不确定度 | 作为分析预算的一部分，不能替代板级抖动测量 |
| 异步时钟组 | 对输入像素、输出像素、DDR、配置和 IMU 等实际跨域关系声明异步 | 每项例外需对应同步器、FIFO 或 IP 的复位/状态同步；不能由时序例外代替 CDC 电路 |
| FIFO Gray 指针 | 四条方向独立施加 `set_max_skew 6.734` | 同时覆盖综合合并后的 Gray/二进制最高位，并检查双角报告是否完整覆盖所有位 |

输出视频寄存器还通过 `PAP_IO_REGISTER` 约束进入 I/O 单元，以减少数据到引脚的延迟及位间偏斜。最终时序审查覆盖 setup、hold、recovery、removal 和脉宽；FIFO Gray 总线偏斜单独审计，因为 PDS 文本汇总显示 All Constraints Met 并不自动代表偏斜数据库中没有失败。

这些约束具有对应的硬件结构和注释依据，但“工具时序通过”仍建立在外部 I/O 预算正确的前提上。开发板实测应补充 HDMI 输入/输出采样可靠性检查，尤其关注已归档输入像素域快角 +0.121 ns 的较小 setup 余量。

### 7.3 CDC、复位和帧一致性

`pose_async_fifo` 使用 Gray 指针及双级同步器传递读写位置，并标注同步寄存器属性；复位清空有效状态，在各自时钟域同步释放。数据 RAM 不逐字复位，通过指针和有效信号阻止访问未写入数据，既保留块 RAM 推断，也明确复位后数据有效性。

`attitude_cdc` 通过事件翻转信号和稳定的数据快照传递姿态。该实现依赖源数据在翻转事件传播与目标捕获期间保持稳定，并非带返回确认的任意速率握手接口；若提升 IMU 更新速率或更改时钟关系，需要重新检查该稳定时间假设。进入渲染任务的姿态随后按源帧锁存，帧槽所有权持续到相应读写完成。

上述结构分别解决亚稳态隔离、跨域数据一致性和帧间所有权。同步器属性、时序例外、Gray 偏斜检查及功能仿真各自覆盖不同问题，验收时应一起审查。

## 9. 结论

项目已形成从 HDMI 输入、真实标定参数驱动的姿态/畸变逆映射、DDR 分块渲染到 HDMI 输出的完整 FPGA RTL 数据通路。分块渲染器在多姿态及组合 DDR 压力仿真中实现了 1080p30 新帧更新，自动 Gamma 与帧缓存并行链路通过像素级仿真；PDS 最终双角时序、资源报告及异步 FIFO CDC 偏斜检查均有归档证据。
