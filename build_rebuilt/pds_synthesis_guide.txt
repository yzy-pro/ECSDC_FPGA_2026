ADS Flow
概述
 
ADS(Architecture
-
Driven Synthesis)
是一款实现

ADS
主要包含
compile
和
synthesize
两大流程，
compile

source code RTL
网表的生成，
synthesize
阶段基于
compile
的
DB
，
mapping
和
optimization
后生成
technology
网表。
 
ADS Flow
完成后，综合工具输出
Technology 
网表文件
(.vm)
等，生成的
vm
网表文件可以用
来使用第三方验证工具做验证工作。
compile
和
synthesize
之间通过
DB
文件进行网表信息传
递，逻辑综合的结果也是通过生成
DB
文件将网表信息传递给
DeviceMap
。
 
下图为
ADS
综合工具实现流程。
 
 
图
 
-
 
ADS Synthesis Design Flow
 
ADS
综合完成后，在工程目录生成的过程文件有

，用于存放全部
log
信息。在工程文
件所在目录中会生成两个子目录，分别为
 
comp
ile
和
synthesize
。

5.1
 
Triple Modular Redundancy(TMR)
 
三模冗余（
Triple Modular Redundancy
，后简称
TMR
）是一种常见的容错设计技术。它采用
三个相同模块执行相同操作，再将这三个模块的输出送到一个表决器中，根据多数相同的输
出作为系统正确输出（
"
三取二
"
原则，
AB~C + (A+B
）
C
）。这三个模块只要不同时出现两个
及以上错误，就能屏蔽掉故障错误的模块，由于三个模块相互独立，两个模块同时出错是极
小概率事件，因此可以大大提高系统可靠性。
 
ADS
实现了
Distributed TMR
，
Block TMR
以及
Local TMR
三种不同的
TMR
技术，它们具有
不同的特点和适用场景。
Distributed TMR
强调模块间的物理分离和独立性，能有效抵抗特定
区域的干扰或故障；
Block TMR
强调模块模块整体性，适用于对数据处理速度和数据完整性
有较高要求的系统；
Loca
l TMR
强调对模块局部处理，通常位于同一物理位置，仅处理时序
逻辑单元，适用于对响应时间要求严格且空间有限的系统。不同的
TMR
实现技术有着不同
的优缺点，具体选择何种方式的
TMR
技术，需要用户根据自身需求自行选择。
 
ADS
将通过设置
PAP_REDUNDANCY_MODE
属性对用户设计应用
Distributed TMR, Block 
TMR
以及
Lcoal TMR
技术。
PAP_REDUNDANCY_MODE
属性可以作用于
module
或
instance
，此外，它可以被继承。

6.2
 
Partition block
适用场景和类型
 
由于边界优化的原因，使用
par
tition block
往往综合结果会变差一些。使用
partition block
的
module
应当满足两点要求：
 
a.
 
边界对时序的影响小，最佳状态是输入输出都有寄存器打拍，其次是这个模块包含完
整的关键路径，前面两个条件都不满足的话，如果边界处时序比较好也可以考虑。
 
b.
 
边界对资源的影响小，这要求模块跨边界的优化比较少。
 
不同类型的
partition block
对应着不同程度的边界优化。
ADS
综合工具提供了四种类型：
"soft"
、
"hard"
、
"locked"
和
"black_box"
。
 
a.
 
soft
类型的
partiti
on block
会在并行综合后，把对应的边界打平再优化。
 
b.
 
hard
类型的
partition block
会进行一些跨边界的优化（但不会打平）。
 
c.
 
locked
类型的
partition block
不会做任何跨边界的优化。
 
d.
 
black_box
类型的
partition block
会把对应的
module
设置成
black_box
。
